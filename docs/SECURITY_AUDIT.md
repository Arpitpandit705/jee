# Security Audit Report — FocusStudy (JEE Companion App)

Date: 2026-10-18 · Scope: Android app (Kotlin/Compose), Firestore rules, build config, git history, bundled assets, build scripts.

## 1. Architecture inspected

- Android app: Kotlin + Jetpack Compose, Firebase Auth (Google Sign-in), Firestore (`firestore_database_id` resource), WorkManager periodic sync, foreground app-blocker service.
- AI: direct Gemini 2.5 Flash HTTP calls (OkHttp), key injected at build time via the Secrets Gradle plugin from an untracked `.env` (`GEMINI_API_KEY` → `BuildConfig`, never committed).
- Bundled data asset: `app/src/main/assets/studyplan/plan.json` — 586 lectures + DPP PDF links, generated by `scripts/build_plan_asset.py` from the PW API using a token kept OUT of the repo (read from `.env` at generation time; the committed asset contains zero tokens).
- Firestore rules: `firestore.rules` (enforced server-side).
- No Storage, no SQL database, no web backend in this repo → items like SQL injection, password hashing, and website cookie/CORS hardening are out of scope by absence; noted below.

## 2. Vulnerabilities found and FIXED (implemented + locally verified)

| # | Finding (severity) | Fix implemented | Verification |
|---|---|---|---|
| 1 | Gemini API key sent as `?key=` URL query → leaks into URL history/connection logs (HIGH) | All 4 Gemini call sites (3 in `GeminiVerificationEngine.kt`, 1 in `GeminiHintEngine.kt`) now send `x-goog-api-key` header; URL contains no secret | grep across `app/src/main/java/com/example/ai` shows zero remaining `?key=`/`.url` secret params |
| 2 | Raw Gemini error body logged (`Log.w ... $responseString`) → could echo request data (MED) | Status code only is logged; body never logged | grep — no raw-body logging remains |
| 3 | PW batch access token appended into launch URL (`?key=...`) → token lands in browser history and target-app logs (HIGH) | `BatchLectureLauncherCard.kt` no longer appends the key to any URL; only non-secret `lec`/`speed` params; https-only guard before launching intents | grep shows no `key=` usage in launcher |
| 4 | Firestore rules let a client spoof/move the `userId` field on any document (MED) | `userIdFieldValid()` guard on users/courses/lectures/daily_plans writes; `sync_logs` are now append-only audit records (update/delete denied); catch-all default deny added | rules syntax reviewed; logic cross-checked against all repository write paths (`SyncLog` always sets `userId`, only creates) |
| 5 | Cloud backup / device-transfer could auto-upload SharedPreferences containing the user's PW token (MED) | `allowBackup=false`; `backup_rules.xml` + `data_extraction_rules.xml` exclude ALL sharedpref from cloud backup and device transfer | manifest + both XML files updated |
| 6 | Demo placeholder courses seeded on first run (functional bug + data clutter) | Replaced with real PW syllabus import via `PwPlanImporter` ( Firestore batch ≤400 ops with 750 ms pauses; profile merge, never wipes) | importer logic reviewed; braced-balance + reference checks pass |
| 7 | Unclosed OkHttp `Response` bodies (resource leak) (LOW) | All response bodies now consumed inside `response.use { }` | 3/3 call sites patched |
| 8 | AI exception logging risk | Hint engine logs only a static message, no exception message (URLs/keys can appear in exception text); no secret can appear since key now travels in a header | reviewed |
| 9 | New Revision-Planner surface had no URL-scheme guard | `openUrl()` allows **https only**, rejects strings containing spaces, guarded intent launch | code review |

## 3. Verified clean

- Git history scan (`git log --all`) — no real secrets ever committed; only the placeholder `MY_GEMINI_API_KEY` in `.env.example` and `.env` is ignored.
- `git ls-files` — no `.env`, keystore, or `google-services.json` tracked.
- Bundled `plan.json` asset + training artifacts — scanned for `AIza…`, `Bearer`, JWT prefixes: clean.
- `scripts/__pycache__` binary false-positive deleted and `__pycache__/` + `*.pyc` added to `.gitignore`.

## 4. Remaining risks (honest disclosure — NOT fixed, why, and what you must do)

1. **Gemini key still ships inside the APK** (`BuildConfig.GEMINI_API_KEY` — ApK reverse engineering can extract it). Proper fix = route Gemini through **Firebase AI Logic** (`libs.firebase.ai` dependency already present but unused) or a Cloud Function proxy, protected by **App Check**. *Manual action:* enable Firebase AI Logic + App Check (Play Integrity) in the console, then migrate the two engines; **rate-limit the Gemini key in AI Studio** (I added a client-side 8-hints/hour limiter in `HintRateLimiter` as an interim mitigation, but it is not server-enforced).
2. **App Check is not enforced in Firestore rules** (`request.app` check). Enabling it before all clients are enrolled would lock out real users, so it is left as a console-side step.
3. **PW batch token stored in plaintext SharedPreferences** on-device. Without `androidx.security:security-crypto` (not in the project's version catalog and I could not verify a new dependency compiles in this environment), the mitigations are: it never leaves the app (no URL, no backup, no logs) and it is the user's own token. Adding `androidx.security:security-crypto` + EncryptedSharedPreferences is a 30-minute follow-up.
4. **Build not compiled in this environment** — no JDK/Android SDK in the sandbox; ALL changes were verified by static cross-referencing (imports, symbol definitions, brace/paren balance, grep sweeps) but **`./gradlew assembleDebug` must be run before release**.
5. **Release build has `isMinifyEnabled=false`** — easier to reverse-engineer; enabling R8 needs ProGuard rule testing (kept off to avoid breaking the app silently).
6. **No CSRF/CORS/XSS/password-hash / cookie-banner / favicon / 404 items** — this repo is a native Android app, not a website; those website checklists do not apply here. Firestore is not SQL, so parameterized-query and password-hashing items are N/A (Firebase Auth handles credentials server-side).

## 5. Deployment steps (exact)

1. **Build & test locally (REQUIRED — cannot be skipped):**
   ```bash
   ./gradlew assembleDebug && ./gradlew test
   ```
   Fix any compile complaints from the new files: `PwStudyPlan.kt`, `PwPlanImporter.kt`, `GeminiHintEngine.kt`, `RevisionPlannerSection.kt` and the `MainActivity` wiring.
2. **Deploy Firestore rules:** `firebase deploy --only firestore:rules`
3. **Ship the app:** build a signed release (`./gradlew assembleRelease`); first run auto-imports the 542-lecture plan for each signed-in user.
4. **After deploy:** enable App Check enforcement for Firestore + register the Gemini key restriction (HTTP referrer/IP restriction) in AI Studio.

Never claim this app is 100% secure — see section 4.
